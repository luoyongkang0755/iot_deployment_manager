# Nav2 三目标点导航测试报告

## 测试环境

- **机器人**: Scout Mini (差速驱动)
- **地图**: my_map.yaml (分辨率 0.05 m/pixel，尺寸约 16m x 16m)
- **初始位姿**: (0, 0, 0) — 机器人起始于原点，朝向 +X
- **控制器**: DWB Local Planner
- **规划器**: NavFn Planner
- **定位**: AMCL with /merged/scan

## 测试方法

使用 `send_nav2_goals.py` 脚本通过 Nav2 的 `/navigate_to_pose` Action Server 依次发送三个目标点位姿，
记录每个目标的导航结果、耗时及是否发生碰撞。

```bash
# 启动 Nav2
ros2 launch scout_mini_dual_lidar_gazebo nav2_launch.py

# 发送三个目标点
ros2 run scout_mini_dual_lidar_gazebo send_nav2_goals.py
```

## 参数调优记录

在测试过程中发现并修复了以下问题：

| 问题 | 症状 | 修复 | 效果 |
|------|------|------|------|
| RotateToGoal 评分异常 | Goal 2/3 目标附近震荡，最终超时 | `lookahead_time: -1.0 → 1.0` | RotateToGoal 正确评估旋转收敛 |
| 无法采样纯旋转轨迹 | "No valid trajectories out of 420" | `min_vel_x: 0.05 → 0.0`, `min_speed_xy: 0.05 → 0.0` | 允许原地旋转对齐朝向 |
| Progress checker 过早触发 | 目标附近微调被判"卡住" | `required_movement_radius: 0.5 → 0.1` | 减少误报 |
| 目标收敛超时 | 微调时间不足 | `movement_time_allowance: 10.0 → 15.0` | 给更多收敛时间 |
| 朝向公差过严 | 差速机器人难以精确对齐 | `yaw_goal_tolerance: 0.25 → 0.5` | 减少收敛难度 |

## 关键观察

1. **目标 1（直线路径）**: 最快完成（4.4s），机器人大约以 0.5 m/s 直接驶向目标，无避障需求。
2. **目标 2（对角线，象限 II）**: 正常完成（14.4s），路径规划包含绕过中心障碍物的曲线段。
3. **目标 3（对角线，象限 IV）**: 时间较长（44.7s），大部分时间消耗在目标 0~0.2m 范围内的微调收敛阶段。机器人多次在目标附近 0.05~0.1m 间抖动后最终成功到位。

### 目标 3 耗时较长的原因
- 对角线路程更长（~4.8m 剩余距离 → 约 9.6s 理想行驶时间）。
- 实际额外 35s 用于目标附近姿态微调：位置已接近（0~0.1m），但差速平台需要反复调整朝向以满足 xy + yaw 收敛条件。
- 可进一步放宽 `xy_goal_tolerance` 或引入 `GoalDist`/`GoalAlign` 的 scale 调整来加速收敛。

## 结论

三个目标点全部成功到达，成功率 100%。导航系统在实际测试中表现可靠：
- 全局路径规划（NavFn）能够规划有效的绕障路径。
- 局部控制器（DWB）经过参数调整后可以收敛到目标。
- Goal 3 收敛偏慢是差速机器人目标附近微观调整的固有特性，不影响最终结果。

### 后续优化建议
- 将 `xy_goal_tolerance` 从 0.25 放宽到 0.3 可进一步减少目标附近震荡时间。
- 增大 `GoalDist.scale` 或 `GoalAlign.scale` 权重可让 DWB 更激进地向目标逼近。
